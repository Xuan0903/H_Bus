# 排班批次新增功能說明

## 功能概述
在排班調度頁面新增了「批次新增」功能，允許使用者透過 Excel 檔案一次性匯入多筆排班資料。

## 功能特點

### 1. 嚴格驗證機制
- **全部或無策略**：只有在所有資料都通過驗證時才能匯入，不允許部分匯入
- **多階段驗證**：
  - 前端格式驗證（必填欄位、格式檢查）
  - 後端存在性驗證（路線、車輛、駕駛員）
  - 內部衝突檢查（批次資料內重複）
  - 資料庫衝突檢查（與現有排班衝突）

### 2. 零覆蓋保證
- 只使用 INSERT 操作，絕不 UPDATE
- 使用 FileLock 確保檔案操作的原子性
- 資料庫事務確保批次操作的原子性

### 3. 使用限制
- 每次最多上傳 500 筆資料
- 只能匯入「正常營運」狀態的排班
- 支援 .xlsx 和 .xls 格式

## Excel 格式要求

### 必要欄位
| 欄位名稱 | 說明 | 範例 |
|---------|------|------|
| 路線編號 | 路線的編號 | 1 |
| 方向 | 去程或回程 | 去程 |
| 日期 | 排班日期 (YYYY-MM-DD) | 2024-01-01 |
| 發車時間 | 發車時間 (HH:MM:SS 或 HH:MM) | 08:00:00 |
| 牌照號碼 | 車輛牌照 | ABC-1234 |
| 駕駛員姓名 | 駕駛員姓名 | 王小明 |
| 員工編號 | 駕駛員員工編號 | D001 |

### 條件欄位
| 欄位名稱 | 條件 | 可選值 |
|---------|------|-------|
| 營運型態 | 路線 1,2,3 必填 | 平日 / 假日 / 寒暑假 |

### 固定值
- **營運狀態**：自動設定為「正常營運」（不需在 Excel 中填寫）

## 使用步驟

### 1. 下載範本
1. 點擊「批次新增」按鈕開啟批次新增視窗
2. 點擊「📄 下載範本」按鈕
3. 獲得包含範例資料的 Excel 範本

### 2. 填寫資料
1. 在範本中填寫排班資料
2. 確保所有必填欄位都已填寫
3. 注意路線 1,2,3 必須填寫營運型態
4. 日期格式：YYYY-MM-DD (例如：2024-01-01)
5. 時間格式：HH:MM:SS 或 HH:MM (例如：08:00:00 或 08:00)
6. 方向只能是：去程 或 回程
7. 營運型態只能是：平日 / 假日 / 寒暑假

### 3. 上傳檔案
- **拖拽上傳**：直接將 Excel 檔案拖拽到上傳區域
- **點擊上傳**：點擊上傳區域選擇檔案

### 4. 檢查驗證結果
系統會自動進行驗證，並顯示結果：

#### 驗證通過
```
✅ 驗證通過，可以匯入 X 筆資料
```
此時「確認匯入」按鈕會啟用

#### 驗證失敗
```
❌ 發現 X 個錯誤，無法匯入
```
下方會列出所有錯誤，包括：
- 行號（Excel 中的行號）
- 欄位名稱
- 錯誤訊息

### 5. 確認匯入
- 檢查預覽表格中的資料是否正確
- 確認所有驗證都通過
- 點擊「確認匯入」按鈕
- 等待匯入完成

## 驗證規則

### 1. 格式驗證
- 所有必填欄位不能為空
- 日期格式必須為 YYYY-MM-DD
- 時間格式必須為 HH:MM:SS 或 HH:MM
- 方向必須為「去程」或「回程」
- 營運型態（如適用）必須為「平日」、「假日」或「寒暑假」

### 2. 資料存在性驗證
- 路線編號必須存在於系統中且已啟用
- 車輛牌照必須存在且狀態為「服務中」
- 駕駛員員工編號必須存在於駕駛員資料中
- 駕駛員姓名必須與員工編號匹配

### 3. 衝突檢查
- 批次資料內不能有重複的排班（相同路線、方向、日期、發車時間）
- 同一車輛在同一時間不能有多個排班
- 同一駕駛員在同一時間不能有多個排班
- 不能與資料庫中已存在的排班完全相同

## 常見錯誤及解決方法

### 1. 「路線 X 不存在或未啟用」
- 檢查路線編號是否正確
- 確認該路線在系統中已啟用

### 2. 「車輛 X 不存在或不在服務中」
- 檢查牌照號碼是否正確
- 確認該車輛狀態為「服務中」

### 3. 「員工編號 X 不存在於駕駛員資料中」
- 檢查員工編號是否正確
- 確認該駕駛員已在系統中註冊

### 4. 「駕駛員姓名與員工編號不符」
- 檢查駕駛員姓名和員工編號是否對應
- 參考系統中的駕駛員資料

### 5. 「車輛 X 在 YYYY-MM-DD HH:MM:SS 已有排班」
- 該車輛在此時間已被安排
- 更換車輛或調整時間

### 6. 「駕駛員 X 在 YYYY-MM-DD HH:MM:SS 已有排班」
- 該駕駛員在此時間已被安排
- 更換駕駛員或調整時間

### 7. 「批次資料中有重複的排班」
- Excel 中存在完全相同的排班記錄
- 移除重複的行

### 8. 「相同的排班已存在」
- 資料庫中已有相同的排班
- 確認是否重複匯入

## 技術細節

### 前端技術
- Vue 3 + TypeScript
- xlsx 庫進行 Excel 解析
- 拖拽上傳功能
- 即時驗證反饋

### 後端技術
- FastAPI
- pandas 處理 Excel 檔案
- FileLock 確保檔案操作原子性
- 資料庫事務確保批次操作原子性

### 安全機制
1. **檔案鎖**：防止併發寫入衝突
2. **事務管理**：確保全部成功或全部失敗
3. **多階段驗證**：層層把關資料品質
4. **權限檢查**：只有調度員可以操作

## 注意事項

1. **資料筆數限制**：每次最多 500 筆，如有更多資料請分批匯入
2. **驗證時間**：資料量大時驗證可能需要幾秒鐘，請耐心等待
3. **錯誤處理**：如發現錯誤，必須修正所有錯誤後才能匯入
4. **重複檢查**：系統會檢查是否與現有排班衝突，避免重複安排
5. **營運型態**：只有路線 1,2,3 需要填寫營運型態，其他路線留空即可

## 測試建議

### 測試案例 1：正常匯入
1. 下載範本
2. 填寫 2-3 筆有效資料
3. 確認驗證通過
4. 成功匯入

### 測試案例 2：格式錯誤
1. 填寫錯誤的日期格式（如：2024/01/01）
2. 確認系統提示日期格式錯誤
3. 修正後重新上傳

### 測試案例 3：資料衝突
1. 填寫與現有排班相同的資料
2. 確認系統提示已存在相同排班
3. 修改時間或車輛後重新上傳

### 測試案例 4：內部重複
1. 在 Excel 中填寫兩筆完全相同的資料
2. 確認系統提示批次資料中有重複
3. 移除重複行後重新上傳

### 測試案例 5：駕駛員不存在
1. 填寫不存在的員工編號
2. 確認系統提示員工編號不存在
3. 更正後重新上傳
